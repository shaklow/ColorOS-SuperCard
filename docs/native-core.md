# 自研 Kotlin 卡包核心：首期

0.2.29 的自研入口位于首页“新卡包预览：校园卡与 LENS”。它使用独立 NativeCardHost 窗口和 NativeCardDeck 内容会话，不创建 vivo CardService、CardCoordinator、原卡片实例或 FunctionBean。原手势入口继续运行现有卡包；记忆卡、卡券和 PAY 尚未迁入新容器，不显示占位卡片，也不更改它们的界面。背景功能保持移除。

首期在新窗口中承载现有校园卡 Material 界面，并用 NativeLensCard 直接读取已保存模式，调用独立 LensCameraSession/LensDisplayBackend。校园卡通过 CardWindowOwner 回调关闭自己的窗口和维护保护，不再访问原窗口。相机沿用相同后端、模式 Intent、触摸缩放与 CANCEL/释放，保护回调由新窗口承接。原容器中的两张卡片继续保留原行为。

## 0.2.30：原版手势与连续动画

0.2.30 使用了 280×450dp、右侧居中的独立浮层；0.2.31 按捆绑原包资源和 PJZ110 实测修正尺寸与锚点，见下节。移除底部翻页按钮，按原交互从右侧手势区域拖入、跟手展开，再按距离或速度完成展开或回弹；在卡包内左右横滑切换，第一张向右滑收起。无障碍保留前后翻页和收起动作。

SystemGestureInput 直接管理 Android InputMonitor/InputEventReceiver；有效区域仍由 GesturePolicy 按已保存的唤出区域和锁屏设置决定。方向确认后才 pilferPointers，底层应用收到取消。展开阈值沿原控制器采用解锁 120dp、锁定 150dp、300dp/s；反向甩动优先取消。锁定时不会预先显示内容，只在完成手势并实际解锁后打开。熄屏继续交给现有 ROM 适配链路，不宣称标准输入监视器能替代厂商 AOD 唤醒。

仅开启校园卡、LENS 时自动由新核心接手边缘手势；仍开启未迁移卡片时，默认保留原完整卡包。首页的预览入口会选用新核心，收起后仍可从原区域滑入这两张卡；首页“唤出悬浮卡片”恢复原完整卡包入口。本次选择不写入持久偏好。NativeGestureCompatibility 只在新核心持有手势时阻止旧控制器重复抢占输入，不参与新核心识别和动效。

NativeGestureViewport 只拦截确认的单指横向手势，纵向滚动、TextureView 相机操作及子视图的禁止拦截请求仍交给内容；多指打断时取消切卡。拖动只更新实际视图的位移与缩放，不截图付款码或相机，不在每个 MOVE 重新布局/创建卡片。前后卡片叠放，下一张从后方揭开，上一张从左侧覆盖；几何回归逐帧验证两种方向、四档密度下均无空隙。旧内容保持挂载直到过渡完成，随后 NativeCardDeck 释放；取消时释放候选卡并回到原卡。松手后从当前位移续接动画，时间按剩余距离和速度在 140–320ms 内调整，连续操作排队续接；锁定、关闭和配置失效立即清理并使旧动画回调失效。

framework-stubs 仅提供 InputEventReceiver/InputChannel 的编译 ABI，使用 compileOnly，不进入 APK。封装检查读取 DEX class_defs，拒绝打包同名平台实现。Android 36 安装回归以 root 测试连接临时覆盖本测试 UID 的 MONITOR_INPUT，测试真实监视器、原始触摸、短滑取消、跟手展开、松手中间帧、卡片横滑、子视图 CANCEL、纵向滚动、连续切卡、首卡右滑收起与动画中锁定清理；测试恢复输入权限、悬浮窗 app-op 和进程动画倍率。API 31/36 同时检查相机 TextureView、多指取消和动画中排队。模拟器中的连续帧证明动画执行与位移续接，不代替目标手机的刷新率/卡顿和 ColorOS 返回手势共存验收。

## 0.2.31：原版几何与整卡出屏

原包 `card_width_straight=288dp`、`card_height=466dp`、`card_min_border=36dp`、`card_margin_bottom=36dp`。`CardViewHelper` 将宽度限制到屏宽减去两侧最小边距，`CarouselAdapter` 水平居中、底部对齐。PJZ110 的 1440×3168px / 640dpi 下，卡片本体为 1152×1864px，左上角为 (144,1160)，底部留 144px。新核心使用真实显示范围，不将状态栏和导航栏再次计入偏移；小屏幕只在必要时限制高度。

`NativeCardSurface` 改为透明舞台，每张真实内容保留自己的背景与 28dp 圆角。舞台扩展到屏幕两侧，移除旧窗口的 12dp 右边距和静止的公用卡片背景，旧卡移动到物理屏幕左边缘之外后才拆卸。反向切换从左侧屏幕外覆盖回来；后方卡片沿原版参数缩小 5%，露出 13.6dp 边缘。后方真实卡片在静止和唤出过程中同样保留，付款码刷新只在卡片完全展开到前台后激活。触摸落在前卡外时不会点击后卡的按钮，轻点可收起。

回归增加原版几何、多密度出屏终点、透明舞台与独立圆角检查。安装测试可用 `am instrument -w -r -e nativeOnly true dev.local.supercardhost.test/dev.local.supercardhost.SettingsStartupTest` 单独执行卡包回归，不运行配置编辑和副屏测试；检查真实窗口和卡片边界、静止叠卡、越过舞台原边界的中间帧、双向横滑、取消、连续切换和锁定清理。

## 0.2.32–0.2.33：主体触摸与原版连续切卡

`getGlobalVisibleRect` 返回 ViewRoot 内坐标，不能直接与 `MotionEvent.rawX/rawY` 的屏幕坐标比较。0.2.32 修复此处混用；真机验证校园卡码区、LENS 按钮/滚动区域及卡片上中下部均可横滑。

0.2.33 将切卡吸附独立为 `CardSnapSpring`，按原包 `QuickSwitchAnimationConfig` 的质量 1、张力 145、阻尼 20、速度上限 20000px/s 和 1px/1px/s 停止阈值求解析解，保留原版轻微回弹。吸附估时取最后一次阈值越界，避免将回弹转折点误判为动画结束。唤出仍按 `DefaultSlideInConfigProvider` 的 0.35s、速度衰减 1/0.9 与 14.4dp 层间偏移分别驱动前后卡片。

卡片位置统一由连续滚动量计算：原版前层位移为 `(cardWidth + 20dp) × position`；后层为 `(13.6dp + cardWidth × 0.025) × position`，每层缩小 5%，Z 轴间隔 8dp；明暗按 0/0.12/0.2/0.3 插值，阴影高度按 20dp 衰减。每张卡片在同一次展开期间只创建、挂载一次；切换只更新位移、缩放、明暗和阴影。退到后方时停止校园码刷新和相机，关闭/锁定时统一释放。

新手势在 DOWN 时接管未完成的切卡动画，保留当帧滚动量；离吸附目标小于 pagingTouchSlop/3 时直接归位并继续交给子控件。唤出进入这一范围后同样可直接横滑，不再等待长尾结束。手势保护只检查当前卡片，后卡的 TextureView 不再遮挡前卡横滑。显示尺寸在创建窗口时缓存，动画帧不查询 DisplayManager。首轮 UI/内容准备移到主线程空闲预热。

相关 API 31 单元测试覆盖原版解析轨迹采样、叠卡几何、DOWN 接管、非活动 TextureView、垂直滚动和多指取消；API 36 真机回归覆盖上中下部、八次连续快速往返、视图实例不变、原位收尾及锁定清理。

## 0.2.34：桌面慢拖与完整唤出时序

解锁后的慢拖放手距离从 120dp 调整到 64dp，避免 ColorOS 桌面上正常的较短拖动因放手速度降为零而收回；40dp 短拖及快速向外反拉继续取消，锁屏距离判定保持 150dp。手势取消、多指、关闭与锁定仍直接结束当前输入。

原版 `AnalyticSpringDriver` 的解析时间并非实际播放秒数：`estimated=9.232803/omega`，播放时长为 `estimated*1000+500` 毫秒，再将播放进度映射回解析时间。0.2.33 漏了这层映射，导致展开过快；此版补齐原时钟和 0.2px 归位条件，并按最长驱动时长结束，避免 550ms 硬切长尾。跟手使用原版刚度 1500、阻尼比 1 的连续重定向弹簧，初次露出不直接跳到手指偏移，松手从实际显示位置续接。

回归覆盖原版时序采样、60/120Hz 跟手轨迹一致性、短拖取消和停顿后的 88dp 慢拖展开；最终还需在真实桌面按不同距离、速度和方向重复验证唤出。

## 0.2.35：真实手指重放 DOWN 与独立收起路径

PJZ110 的真实触摸在 `pilferPointers` 并出现新窗口后，会重发原始 DOWN：事件时间和原位置不变，downTime 可能相差 1ms。之前将它视为下一次手势，立即取消已认领的输入；ADB 注入没有此重放，导致前次验证遗漏。`GestureDown` 仅在当前仍有输入决策且设备、来源、显示、指针、原始时间与位置一致时忽略重放，保持跟手及 VelocityTracker；新的触摸和系统 CANCEL 继续结束旧输入。触发距离恢复原版解锁 120dp、锁屏 150dp。

空白处收起不再复用唤出的 `AnalyticSpringDriver`。原版非折叠屏使用 `SpringFormulaInterpolator` 的独立 0.45s 曲线；处于后续卡片时使用 0.65s，同时按 LinearLayoutManager 的默认平滑滚动回到第一张。`CardDismissMotion` 将此回收滚动和整叠退出同时驱动，避免旧卡停在左侧后被整体位移带回，形成平铺横排。回归检查真实事件重放样本、首卡与第二张收起时序，以及第二张点击舞台空白处时的回收中间帧。

## 0.2.36：空白点击只收起卡包

之前高度仅覆盖卡片舞台的窗口设置了 `NOT_TOUCH_MODAL | WATCH_OUTSIDE_TOUCH`，收到外部点击通知的同时，桌面仍会收到原始 DOWN/UP。窗口改为全屏透明且保持触摸模态，卡片舞台作为底部固定大小子视图，仍保留 36dp 底边距；空白点击由当前窗口完整消费，再执行原版收起动画。命中测试与滑动坐标改用舞台的屏幕位置。

真机回归在卡包下方放置实际可点击窗口，点击卡片上方空白后，断言卡包完成叠放收起且下方窗口没有收到 DOWN 或 UP；同时核对全屏输入边界和原版卡片几何。

## 0.2.37：PAY 迁入自研核心

NativePayCard / PayCardSurface 管理快捷入口和支付页，NativePaySession / NativePayBackend 管理安全副屏、触摸、当前任务与释放，复用原启动协议与现有用户路由。仅启用已迁移且已就绪的 PAY、校园卡和 LENS 时自动接手；未迁移卡片或 PAY 功能保留原路由。完整边界见 [自研支付卡](native-pay.md)。

## 0.2.39：卡券迁入自研核心

NativeCouponCard / CouponCardSurface / NativeCouponSession 接入 `staging`，原配置排序、窗口几何与外层动效保持一致。列表按可见项复用视图，二维码后台准备；钱包连接、账号确认与补码继续复用既有客户端。整包刷新由自研窗口身份持有，切卡不重复查询，迟到的旧窗口事件不能清掉当前会话。支持详情、返回、钱包查看、原图与本地移除，详细边界见[自研卡券](native-coupon.md)。原完整卡包仍为启用记忆等未迁移卡片的配置保留。

## 归属与系统边界

- NativeCardDeck 是不依赖 Android 的 Kotlin 内容状态机，负责单一活动卡片、失败回滚、关闭和旧异步结果令牌。
- NativeCardHost 负责自己的 WindowManager 窗口、内容挂载、连续过渡和关闭；窗口始终 FLAG_SECURE，切卡动画完成后清理上一张内容，相机内部触摸及纵向模式列表滚动保留。
- NativeCardRuntime 处理入口、卡片配置和屏幕状态；仅启用已迁移且已开启的卡片，锁定、熄屏、关闭总开关或配置失效时移除窗口。
- ColorOsCardAccess 独立处理真实锁屏检查及 ActivityStarter 解锁。需要实际解锁后才打开内容；取消、超时和过期回调不会重新打开卡片。
- RootDisplayClient 在自研核心初始化时独立连接，原厂 DEX 准备失败不妨碍其建立连接。客户端与 daemon 的认证、固定显示槽位和协议不变。
- 私有 UI 档案仅通过 View/Bundle/Consumer 跨加载器通信，继续隔离 SystemUI 的 AndroidX/MDC 与资源。

## 验证与推广门槛

API 31/36 验证窗口导航布局、内容归属、失败清理、重开和旧令牌失效。Android 36 安装回归创建真实独立浮层，操作真实 Material 导航、验证 FLAG_SECURE、关闭/重开和锁定门禁清理，再将真实副屏 TextureView 接入该容器，沿生产 LensDisplayBackend 启动 Activity 并注入触摸。

CI 使用 `--secure-native` 明确要求可 root 的测试模拟器：以 root adbd 启动 instrumentation，通过 UiAutomation 的测试专用权限覆盖临时授予本测试 UID CAPTURE_SECURE_VIDEO_OUTPUT，创建真实 SECURE 虚拟显示并核对系统显示标志。仅对显示信任、输入注入及后台 Activity 启动采用 shell 权限身份，避免全量 shell 身份覆盖本测试 UID 的安全显示权限。覆盖生效和 finally 撤销后的权限状态均有断言，生产权限、代码和 root daemon 认证没有放宽。测试不请求付款、不获取真实相机素材、不修改用户授权链接。普通设备不带该参数时不宣称完成安全显示验证。

标准模拟器缺少目标 ColorOS、Vector、原相机 HAL，以及真实小布/钱包账号。模拟器结果不能证明目标 ROM 的解锁入口、原系统相机全部模式、系统返回手势共存或 root daemon 的实际策略已验收。0.2.30 的默认接管范围限于只启用已迁移卡片的配置；完整混合卡包仍保留原路由。后续迁移 PAY，再按界面约束逐张迁移记忆和卡券。自研核心首期完成不等于全部原厂运行代码已删除。
