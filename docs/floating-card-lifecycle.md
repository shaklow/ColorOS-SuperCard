# 浮层挂载生命周期

0.2.19 将校园卡与 LENS 的配置监听、排队刷新和定时任务收拢到 Kotlin `FloatingCardScope`。原卡片 View、WindowManager、手势、支付虚拟屏和触摸路由不由此组件管理。卡券和记忆界面不接入此组件。

每轮挂载生成独立 Token，只注册一个 ContentObserver。相同 Runnable 的待执行刷新合并为一次；执行后移出队列。移除卡片先失效 Token，再取消该组件的排队任务并注销监听。监听注册失败可在下次挂载重试；注销失败被记录，旧通知仍由 Token 检查拒绝。Observer 对作用域使用弱引用，避免异常注销路径通过监听回调继续持有卡片。

校园卡取码继续保留原请求 generation、任务取消、锁屏/亮屏/可见面积检查、过期拒绝与离屏清码。工作线程提交结果时还必须匹配发起请求的挂载 Token；移除或重新挂载后直接拒绝排队。预览不启动监听或取码，失活卡片不重新排入倒计时。此轮不改变 Provider、授权、付款码内容或安全窗口标记策略。

LENS 的设置变更先准备并绑定新界面，再替换旧内容；创建或绑定失败时保留原内容。原 FunctionBean 仍由原加载器的 Gson 读取，点击继续交给原事件处理器。重复执行内层初始化不会再添加第二份 LENS 内容。校园卡配置变化先清码，再准备新界面，失败时保留已经清码的旧界面。

## 验证边界

- API 31 / 36 的作用域测试覆盖重复挂载、移除前后排队任务、重新挂载后的旧通知与异步结果、刷新合并、定时取消，以及监听注册/注销异常。
- 校园卡宿主 View 测试使用私有 UI 不可用时的降级界面，检查反复真实挂载、移除清空展示内容和配置创建失败保留旧界面。测试不取码，不代表完成校园卡服务验收。
- 离线 LENS Hook 回归增加重复初始化检查，继续检查原卡片所有者、子 View 保留、失败回退和未知 ABI 拒绝。
- Android 36 已安装统一 APK 检查真实作用域的监听注册、重复挂载拒绝、移除后任务取消和重新挂载结果隔离，继续执行四个设置入口、非 Activity 浮层及真实私有 UI 检查。
- ColorOS + Vector 的系统手势、相机和实际取码仍需真机验收。
