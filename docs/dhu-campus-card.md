# 东华校园卡

卡片管理中新增独立的“东华校园卡”，沿用原管理页的启用、停用和排序。第一次升级会把新卡片追加到现有卡片列表，不重排已有卡片；后续保留用户的开关和位置。

## 配置与使用

在卡片管理中点击东华校园卡的设置按钮，或点击运行时卡片中的“设置”。粘贴学校支付页面的完整授权链接，点击“保存授权链接”。保存后会立即验证；网络暂不可用时仍保留已保存的链接，可以稍后重新验证。

支持更新、验证和清除链接。设置只接受学校的 `ecardhall.dhu.edu.cn:9001/thirdweb/authpaycodedhu` 地址以及完整的 `timestamp`、`token`、`sign` 参数。链接只保存在应用私有配置中，不写入全局系统设置，不作为外部 Intent 参数接受。

解锁并打开卡片后获取付款码，展示期间每 60 秒刷新。点击二维码或“刷新”立即更新，长按二维码或点击条形码、数字提示可放大。隐藏卡片、切换到其他卡片、熄屏或锁定后清除码图并停止获取。设置预览不联网、不生成演示付款码。

更换链接时清除旧会话，取消旧客户端并通知显示中的卡片重新获取；旧请求结果会被配置版本和视图请求代数检查丢弃。刷新失败或到达下一次刷新时间后遮蔽旧码，不能离线继续使用。倒计时是“下次刷新”，不代表未经验证的服务端有效期。

## 接入协议

- 首次请求授权 URL，解析服务端 HTML 的隐藏 `#qrcode0`，严格接受 20 位数字。
- 用独立 CookieManager 保持该链接的会话，POST `/ThirdWeb/GetBarCode`，表单为 `acctype=000&json=true`。
- 验证 `IsSucceed` 和 `Obj[0]`；会话无效返回 HTML、401/403 或 `Msg=-404` 时，用原授权 URL 重建一次会话。
- QR 使用 M 纠错级别，条形码使用 CODE128，两者编码同一个原始字符串，保留前导零。
- 不连接网页中的内网支付结果 WebSocket。原生卡片只取码和展示，不提交支付或订单。

网络和 Cookie 均由模块应用进程中的 `DhuPayProvider` 管理，避免 SystemUI 的明文 HTTP 策略和配置存储混用。应用仅对学校域名允许 HTTP。Provider 仅允许模块本身及 SystemUI UID 取码；读取、修改授权 URL 仅允许模块自身。付款码只在内存中保留，不记录链接参数、会话或码值到日志。

## 验证

`python tools/test_dhu_pay.py` 编译并运行生产协议解析、HTTP 会话客户端和编码器的离线测试。测试使用固定响应的 HTTP 连接替身、Bitmap 像素存储替身及真正的 ZXing 解码器，不访问学校服务。测试依赖逐个校验 SHA-256；`--offline` 要求已有缓存。

已覆盖地址校验、HTML 首码提取、Cookie 隔离、刷新表单、一次会话恢复、重定向限制、异常付款码、响应大小上限、取消请求以及包含前导零的 QR/CODE128 编码解码一致性。该测试已经接入 `ci/build.ps1`。

完整验证仍需执行正常统一 APK 构建，并在目标 ColorOS/Vector 设备确认卡片管理、生命周期、锁屏、放大窗口和实际扫码显示。授权链接的长期有效期和付款码的服务端实际有效期仍未确认。
