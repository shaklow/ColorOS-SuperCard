# 手势与浮标设置

0.2.25 将入口统一到应用内 `GestureAreaActivity`，使用私有 Material 界面档案。旧 Java 页面、`NativeFloatSettings` 与原侧边栏浮标页的混淆控件适配已删除；首页、卡片管理页、侧边栏中的卡包设置入口及原设置链接均进入新页。

页面支持拖动范围及两端点、位置/长度滑块、连续透明度、非锁屏侧滑、四种锁屏方式、浮标显示及自动隐藏。范围预览提供键盘和无障碍位置调整。恢复默认外观仅恢复范围与透明度，保留唤出方式和显示开关。

| 组件 | 职责 |
| --- | --- |
| GestureSettingsSurface | 主题、布局、触摸和无障碍；只使用框架 Bundle/Consumer 与宿主通信 |
| GestureAreaActivity | Activity 生命周期、事件转发、平台请求与主线程调度 |
| FloatSettingsState | 不可变显示快照、滑块换算和显示状态 |
| GesturePolicy | 纯 Kotlin 锁屏、熄屏、非锁屏策略与不可变区域；浮标显示规则与触发规则分离 |
| GesturePolicyAdapter | Secure 设置读取和 Android Rect 转换 |
| GestureSettingsRules | 无平台依赖的范围解析、缩放/取整、编辑下限、默认值、侧滑标记及透明度规则 |
| FloatSettingsSession | 合并保存队列、确认值、读请求代数、预览节流/续租、断线恢复和关闭 |
| FloatPreviewLease | SystemUI 中按调用 UID、页面标识和单调时钟代数隔离预览 |
| CardConfiguration / GestureHandle | 原设置写入协议和实际非触摸浮标窗口 |

读取和编辑不会混入侧边栏自己的浮标配置。保存沿用现有 Secure 设置键；卡片唤出、切卡、收起及业务入口未改，记忆和卡券界面未改。

范围和透明度分别延迟 600/350 ms 合并保存，松手立即提交。写入串行执行，同一项保留最新值；写入确认不得覆盖其后产生的拖动值。失败恢复最后确认值并提示。关闭页面取消读取、预览和恢复计时，解除界面回调，已接受的保存继续排空。

每次恢复页面建立新的预览代数。暂停使旧读回调失效，并发送带归属的预览结束；旧预览回调不会发送无归属的结束请求。SystemUI 同时检查页面归属与五秒请求期限，拒绝较旧页面覆盖或清除较新预览；结束记录保留，先结束后到达的预览不能复活。浮标原有十秒自动过期仍保留。预览不写入真实手势范围。

API 31/36 验证合并写入、关闭后排空、读写乱序、重复回调、保存失败、恢复、归属与请求期限，以及新页的深浅色、320/600 dp 和大字体布局。Android 36 安装回归使用生产会话和独立测试存储操作真实 Material 控件，并检查实际预览端点不能被旧页面干扰。测试不修改真实设置值。

0.2.26 统一设置读取、默认值修复、实际触发区域和浮标提示的范围规则。保存格式仍为四段有限浮点数，按来源宽度缩放，再取整到物理像素；非法或退化区域不参与触发。已保存的短范围可以读取且不被自动扩展，用户编辑范围时沿用 4% 下限。只读取不会改写设置。侧滑开关按完整标记识别，避免子串误判。

0.2.27 将区域和分支判断抽到纯 Kotlin GesturePolicy，GestureConfigBridge 仅投影原厂 ABI，GestureHandle 读取同一决策。熄屏分支不会绘制提示，但仍按自身开关处理手势。矩阵测试覆盖总开关、侧滑、损坏范围、锁屏/熄屏独立开关、四种方式和未知方式。

0.2.28 使用 RuntimeBootstrapSession 区分可重试的准备与只执行一次的 Hook/原服务安装。准备阶段以 1/3/10/30 秒退避最多重试四次，安装阶段失败不重复 Hook，并在诊断中报告需要重启进程。RuntimeEventLoop 统一接收器、750ms 状态同步和初始诊断任务的归属；注册失败回滚，关闭后旧通知失效。配置协议提前提供诊断并保证单次注册。

后续实现自研 Kotlin 卡包运行时与浮层，验证安全显示、锁屏与触摸配合后逐张迁移。必要的 ColorOS、钱包、小布接口保留独立适配层。每阶段保留独立 PR、完整构建和安装回归。
