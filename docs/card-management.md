# Material 卡片管理

0.2.23 将卡片管理独立为 `CardManagementActivity`，使用既有私有 Material 界面档案，与设置首页一致。卡券浮层、记忆卡片内容、PAY/LENS/校园卡运行窗口及手势不改造。

## 操作与入口

- 同一列表显示所有卡片，使用开关启用或停用；停用保留位置，运行时仍按原配置筛选启用的卡片。至少保留一张启用卡片，兼容旧配置全部停用后重新启用。
- 长按手柄拖动排序，也可使用带卡片名称的上移、下移按钮。排序使用相同模型，拖动只接受本页当前列表内的本地卡片。
- PAY、相机进入原 `CardEditActivity`，继续使用原功能选择与排序；校园卡进入授权设置；卡券打开原钱包管理入口。记忆卡片没有新增编辑器。
- 首页“管理卡片”直接打开新页。旧 `com.vivo.card.setting.CardSettingActivity` 组件名通过 manifest alias 指向新页，缓存快捷方式与原卡片入口继续有效。合包时跳过被 alias 替代的原管理 Activity，原功能编辑器继续保留。

## 配置与保存

沿用 `Settings.Secure.card_setting_data`，没有第二份数据库。模型从原 JSON 投影卡片标识、标题与开关，编辑只改变 `enable` 或卡片数组顺序。功能、皮肤、根级开关及未知字段均保留，不经过原 Gson 模型重新序列化。

仅当原配置缺失时，调用既有 `CardDataInitializer` 完成首次初始化和旧 SharedPreferences 迁移。损坏、重复标识或不合法开关不会触发重置。初始化使用 Application Context，不持有页面。

所有本页读写在单工作线程进行。提交前比较原始快照，保存后读回确认；过期页面不能直接覆盖已变更的功能配置。旧设置接口没有跨进程 CAS，比较与写入间仍不是原子事务，因此读回变化会报告失败并重新读取，不回滚其他编辑器的数据。页面关闭后不再处理结果，已接受的写入允许完成。

配置变化由 ContentObserver 刷新；通知先在工作线程核对原始内容，已确认写入的延迟通知不触发多余刷新，避免禁用控件打断长按。保存期间恢复已确认的开关并禁用修改；失败展示实际读回值，不能把本地乐观开关当成保存成功。未取得设置保存权限时可查看现有配置，编辑被禁用，并提供运行状态与授权入口。

## 加载边界与验证

新增界面仍封装于 `assets/dhu-ui.apk`。宿主仅交换框架 View、Bundle 和 Consumer，不引入 MDC/AndroidX 资源冲突，也不改变原厂 0x7f 资源块或原 DEX。

验证覆盖 API 31/36 配置保留、无效配置、最少卡片规则、旧快照、写入失败及读回变化；Material 控件、拖动归属、排序按钮、权限状态、320/600 dp 与大字体深浅色布局。离线检查实际合包 manifest 与原 DEX 反射签名。Android 36 安装后测试实际开关保存、上移、真实长按拖动、长按期间的重复通知、外部配置变更刷新、原功能编辑入口、旧组件 alias 和首次初始化。发布比较既有 40 张渲染图，并检查新增管理页渲染。
