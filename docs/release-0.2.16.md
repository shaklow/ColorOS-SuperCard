# 0.2.16 钱包连接修正

本次只调整钱包连接、读取失败提示和回归验证。卡券与记忆继续使用原浮层界面、布局和交互，没有新增卡片页面。

## 连接修正

- 在 `onPackageReady` 使用最终应用 ClassLoader 安装钱包桥接。`onPackageLoaded` 中的 default ClassLoader 不能保证包含 AppComponentFactory 后续调整的依赖。
- 先通过现有、验证发送方身份的有序广播进行轻量 `ping`；已经运行的钱包可以直接连接，不再被固定 Seedling Provider 的可用性提前阻断。
- 未连接时才尝试已知的空实现 Provider 预热。后台入口缺失或权限阻止时，仍有一次有界的接入等待；不调用钱包写入方法，不强行弹出钱包 Activity。
- 握手不读取账号、不触发原生查询、不占用查询 BUSY 状态。旧钱包进程返回 `unsupported_operation` 时兼容已有协议；新进程继续使用发送方 UID/包名校验。
- 单次连接只发起一次真正的原生查询，保留外层三轮重试，防止在 18 秒原生读取期间叠加查询。
- 保留未登录、账号变化、服务关闭、接入无响应、超时和原生读取失败等原因，仅替换原空状态中的固定文案。页面与日志不显示原生异常中的账号、链接或券码数据。

## 验证边界

连接回归覆盖已运行/冷启动的钱包、后台预热失败但接入成功、缺失接入、旧进程协议、原生错误、超时、格式错误、取消、锁屏与不支持的 Android 版本。测试脚本化钱包传输，验证真实客户端的流程；不会在测试中访问用户钱包或账号。

完整合包、启动与浮层回归由 CI 执行。标准 Android 模拟器没有 ColorOS 钱包与 Vector，不能确认用户手机的这次报错已经解决。真机需在升级并重启后核对钱包作用域、读取结果；若仍失败，新的具体错误提示及 LSPosed / Vector 日志可区分接入与原生读取问题。
